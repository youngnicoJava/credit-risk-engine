Los tres backends reales se iniciaron en modo Quarkus dev con los realms de desarrollo existentes. Se mantuvieron los datos históricos; no se enviaron formularios de creación, aceptación, desembolso ni resolución. Kafka quedó deshabilitado. Para una sesión de lectura se usaron flags de proceso quarkus.flyway.migrate-at-start=false y quarkus.scheduler.enabled=false; no se cambió application.properties ni el comportamiento normal de arranque.

No se recrearon bases, tablas o volúmenes. Docker Desktop y los servicios existentes se iniciaron; Keycloak Dev Services importó los realms locales. Esta actualización no publica los cambios previos de código encontrados en el working tree.
